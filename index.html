How it works

A human asks. An AI writes the code. The robot does it.

[01] Human asks
"Pick up the orange and put it in the pan."
— a person · plain English
[02] AI writes code
put_orange_in_pan.py
from robot_sdk import arm, gripper, find_objects

orange = find_objects("orange")[0]
pan    = find_objects("pan")[0]

arm.move_to(orange.pose, z_offset=0.10)
arm.move_delta(z=-0.10); gripper.close()

arm.move_to(pan.pose, z_offset=0.20)
gripper.open()
[03] Robot does it

Architecture Three running tiers · one artifact channel

L1 Intelligence (orchestrator + dev/eval agents) writes Python — those Skills are an artifact, not a service — and submits them to L2 Runtime (Agent Server), which calls L3 Substrate (hardware drivers + sim bridges + ML services). Humans hand a task graph to L1 and step out of the loop.

How a skill ships Lifecycle of a skill graph

A task is a DAG of the skills shown above. The orchestrator walks the graph, fans out one Claude agent per (skill × sim target), each agent writes Python that the sandbox runs against the sim or hardware, and an evaluator agent reviews the recording before the skill ships into the library.

example skill graph pick-up-object → place-object → pick-and-place ↑ a graph of those skills (any of them) flows through the stages below
[01] AUTHOR Define Hand-curated graph.json — skill nodes, dependencies, and the sim task_env they target.
[02] PLAN Dispatch Orchestrator (8765 / 8766) walks the DAG, picks skills whose dependencies are done, gates by dev_mode.
[03] FAN-OUT Spawn agents Claude Agent SDK clients — one per skill × per sim target, in parallel.
dev agent · target_1 dev agent · target_2 dev agent · target_3
[04] RUN Execute Each agent posts Python to agent_server /code/submit; sandbox runs it against the per-target sim or hardware.
[05] SHIP Eval & ship Eval agent reviews the recording — pass marks the skill done, unblocks downstream skills in the graph.

What we built Open-source · MIT

The two tiers of the platform we shipped: L1 Intelligence (the orchestrator that walks the task graph and fans out Claude SDK agents) and L2 Runtime (the agent_server that sandboxes their code and drives the robot). Both MIT, both open source.

Install (Sim + Claude Code)

No hardware needed — runs entirely in simulation. Requires conda plus Claude Code (default) or OpenClaw for Ollama / Gemini support.

curl -fsSL https://raw.githubusercontent.com/TidyBot-Services/Tidybot-Universe/master/setup.sh | bash -s -- YOUR_ENV_NAME

Follow the instructions printed at the end — start your agent in the skill agent directory and type /xbot-dev.
